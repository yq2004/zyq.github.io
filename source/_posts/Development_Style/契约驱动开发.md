**契约驱动开发 = 先约定系统之间怎么说话，再分别实现系统。**

先定义：

- 前端怎么调用后端；
- 后端返回什么；
- 长任务怎么推送事件；
- 错误长什么样；
- 数据实体有哪些状态；
- 导出包结构是什么；
- 版本怎么演进；
- 哪些行为必须稳定。

## docs/scope.md -- 写项目做什么，不做什么

```markdown
# scope
## in scope
- 用户可以创建对话
- 用户可以上传知识库文档
- 系统可以基于知识库内容回答问题

## out of scope
- 暂不支持多人协同编辑
- 暂不支持插件市场
```

这个文件的意义是防止项目无限膨胀。

## docs/glossary.md -- 写统一术语

```markdown
# glossary

- conversation: 一组用户与系统消息上下文
- message: conversation内的一条用户或助手消息
- run: 一次异步执行过程，包含工具调用、子专家调用、模型输出
- KnowledgeBase: 用户上传并构建索引的一组知识材料
```

术语消歧，防止不同开发者对术语理解不同而造成的业务混乱。

## docs/architecture.md -- 写模块关系

```markdown
# architecture
frontend 调用 API server
API server 创建 run
run engine 执行 agent
agent 可以调用 sub-agent、tool
run engine 通过事件流把中间状态推给frontend
```

## docs/adr/0001-contract-first.md

> ADR: Architecture Decision Record

```markdown
# ADR 0001: Use Contract-First Development

## Decision
在编码前，我们定义了API,事件和模式的契约。

## Context
前端，后端，Agent Runtime

## Consequences
- 前端需要能mock，以防后端还没完成某些模块的开发
- 后端改动必须依照已有契约或创建新版本的契约
- 契约的有效性也是交付的一部分
```

这不是写给Coder Agent看得，是写给未来的自己或者架构设计者看的，当以后设计架构的时候对某些模块感到疑惑，可以回头看ADR来了解。

## contracts/openapi/v1/openapi.yaml -- 写HTTP API，即前端如何调用后端

```yaml
openapi: 3.1.0
info:
	title: Example API
	version: 1.0.0

paths:
	/conversations:
		post:
			operationId: createConversation
			summary: create a conversation
			requestBody:
				required: true
				content:
					application/json:
						schema:
							type: object
							required: [title]
							properties:
								title:
									type: string
			responses:
				"201":
					description: Created
```

## contracts/schemas/v1/common.schema.json -- 写通用数据结构，比如ID、时间、分页、状态枚举

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "common.schema.json",
  "type": "object",
  "$defs": {
    "EntityId": {
     	"type": "string",
      "minLength": 1
    },
    "Timestamp": {
      "type": "string",
      "format": "date-time"
    }
  }
}
```

## contracts/schemas/v1/problem.schema.json -- 写统一错误格式

```json
{
  "schema": "",
  "type": "object",
  "required": ["type", "title", "status"],
  "properties": {
    "type": { "type": "string" },
    "title": { "type": "string" },
    "status": { "type": "integer" },
    "detail": { "type": "string" }
  }
}
```

前端就知道所有错误都按同一种格式处理

## contracts/events/v1/asyncapi.yaml -- 写实时事件

比如Agent输出token、工具调用情况、任务完成进度。

如果项目没有长任务、没有实时输出，可以先不写这个文件。

```yaml
asyncapi: 3.0.0
info:
	title: Example Events
	version: 1.0.0
	
channels:
	runEvents:
		address: /runs/{run_id}/events
		messages:
			RunStarted:
				payload:
					type: object
					required: [event_id, run_id, type]
					properties:
						event_id:
							type: string
						run_id:
							type: string
						type:
							const: run.started
```
