1. 两数之和 🟩

I: nums: List[int]; target: int

O: index: List[int]（长度为2的下标数组）

Cons: nums[index[0]] + nums[index[1]] == target；恰好存在一个有效答案；同一元素不能使用两次；2 <= len(nums)。

核心思路：遍历每个数 x 时，问题转化为”x 之前是否出现过 target-x”，即 **查找 → 用哈希表把 O(n) 查找降为 O(1)**。

一题多解：

解法 时间 空间 备注
暴力枚举 O(n²) O(1) 双重循环
两遍哈希 O(n) O(n) 先全建表再查，注意重复元素覆盖问题
一遍哈希 ✅ O(n) O(n) 边查边存，天然避免用自己

易错点：

  1. 一遍哈希必须先查后存。若先存再查，当 target = 2*x 时会匹配到自己。
  2. 返回的是下标不是值；且题目保证有解，末尾 return [] 只是语法兜底。

深度思考：一遍哈希的正确性在于：当遍历到 i 时，哈希表里恰好是 [0, i-1] 的所有元素——这正是”另一个数只能出现在别处”的完整搜索空间。这是用空间换时间的查找类问题的通用范式。

49. 字母异位词分组 🟨

I: strs: List[str]

O: List[List[str]]，外层 List 的每个元素是一组互为异位词的 str

Cons: 0 <= len(strs[i]) <= 50，均为小写字母；异位词：字母相同但排列可能不同的词。

核心思路：互为异位词 ⟺ 存在相同的”规范签名”。分组问题 = 找一个可哈希的等价类签名。

理解异位词：1. 排序后相同；2. 各个字母出现的次数相同的词。
前者约束更强（排序签名 O(klogk)，计数签名 O(k)）。

一题多解：

签名方式 单词处理 时间 空间
排序签名 tuple(sorted(s)) O(klogk) O(nk·logk) 代码最短，面试先说
计数签名 ✅ O(k) O(nk) 26 维计数向量转 tuple 作 key

易错点：

  1. 强转 tuple()：list 可变、不可哈希，无法作为 hash key；tuple 不可变所以可以。（延伸：frozenset 也可哈希，但会丢失计数信息，不能用于本题）
  2. defaultdict 常用接口：d[key] 不存在时自动创建默认值；append 配 list、int 配计数、set 去重收集。

深度思考：本题的本质是等价类划分。凡是”按某种不变量分组”的题，套路都是：① 定义不变量（签名）；② 保证签名相等 ⟺ 同组（双向蕴含）；③ 哈希聚合。排序签名和计数签名只是两种不同的不变量选取。

128. 最长连续序列 🟨

I: nums: List[int]

O: int，最长连续数字序列的长度

Cons: 要求 O(n) 时间复杂度（这是本题的灵魂约束，排解法直接否决）；序列元素在原数组中不必相邻；数值可达 ±10⁹ 且可能有重复。

核心思路：O(n) 排除了排序 → 只能用 set 做 O(1) 查找。关键洞察：只从连续段的起点开始向右探测，每个数最多被访问两次，整体 O(n)。永遠只从 最底层 开始做起：看到 num 就探测有没有 num-1，直到不存在 x-1，这才是最底层（段起点）。

一题多解：

解法 时间 空间 备注
排序后线性扫 O(nlogn) O(1) 不满足 Cons，面试中可作为引子被否决
HashSet + 起点探测 ✅ O(n) O(n) 正确性依赖”跳过非起点”

易错点：

  1. 忘记去重（应遍历 nums_set 而不是 nums），重复元素会让内层 while 重复跑，最坏退化 O(n²)。
  2. 空数组要返回 0（本代码天然正确，因为循环不执行）。
  3. if (num-1) in nums_set: continue 是复杂度的全部来源，漏掉就超时。

深度思考：为什么是 O(n)？内层 while 只在一个连续段的起点被触发，而所有段的起点探测的总步数 ≤ n。即：看似双重循环，实则均摊。这与”并查集路径压缩””KMP 均摊分析”是同一类复杂度论证方式。

283. 移动零 🟩

I: nums: List[int]

O: 无返回值，原地修改（in-place），使所有 0 移到末尾，非零元素保持原有相对顺序

Cons: 必须原地，尽量少操作次数；不开辟额外数组。

核心思路：快慢指针 —— l 指向”下一个非零元素应放的位置”，r 扫描全数组；r 遇到非零就和 l 交换。l 左边永远是已处理的非零前缀。

一题多解：

解法 时间 操作次数 备注
新开数组 O(n) — 违反 Cons
先删零再补零（两次遍历）✅ O(n) 写次数更少 非”交换”而是”覆盖”，赋值次数更优
快慢指针原地交换 ✅ O(n) 最多 n 次交换 见下方代码

易错点 / 思考记录：

  1. 如果所有非零元素都是大于零，且不要求保持元素相对位置，可以用冒泡排序，而且效率也不高（排序的条件太强）。
  2. 要保持原有元素的相对位置…双指针，两个指针都不断向前，只在特定时候更新。
  3. 2.中的双指针属于快慢指针，双指针可以建模为双端指针（l=0,r=n-1 快速收敛）和快慢指针（l=r=0，有一方更快）。更快一般是：r 不断向前遍历，l 只在特定时机移动几下；或者 r 一次移动多步，l 每次移动 1 步，但本质是一样的。

深度思考：交换法中 l≤r 恒成立，且 [0,l) 全非零、[l,r) 全零是循环不变式——用循环不变式证明双指针正确性是通用方法论。另注：”覆盖+补零”版本交换次数更少，若面试官追问优化点可答。

11. 盛最多水的容器 🟨

I: height: List[int]，height[i] 是第 i 条垂线的高度

O: int，容器可容纳的最大水量

Cons: area = min(h[l], h[r]) * (r-l)；n >= 2；不能倾斜容器。

核心思路：面积由短板和宽度共同决定。对撞双指针 + 贪心：每次移动较短的一侧——因为保留短板、缩小宽度不可能更优，只有换掉短板才有机会变大。

一题多解：

解法 时间 空间 备注
暴力枚举所有 pair O(n²) O(1) 会 TLE，但面试先口述它体现思维过程
对撞指针 + 贪心 ✅ O(n) O(1) 核心是证明移动短边的正确性

易错点：

  1. 移动的是较短一边；两边相等时任移一边均可（可证明不丢最优解）。
  2. 别写成移动较长的一边——那样 min 可能变小且宽度必变小，严格更差。

深度思考（贪心的正确性）：设当前 (l, r)，短板为 h[l]。若固定 l 不动、让 r 左移，则宽度减小且高度仍被 h[l] 封顶，面积必然不增 → 所有含 l 的其他组合都被当前解支配，可以安全丢弃 l。每一次移动都在排除一批被支配的状态，这就是对撞指针贪心的一般论证模板。

15. 三数之和 🟨

I: nums: List[int]

O: ans: List[List[int]]，所有和为 0 的不重复三元组

Cons: 三元组内三个下标互不相同；答案不能包含重复的三元组（去重是最大难点）；n <= 3000，暗示 O(n²) 可过。

核心思路：a+b+c=0 枚举一个数 a 后退化为 two-sum。排序后固定 i，对 [i+1, n-1] 区间用对撞双指针找两数之和 -nums[i]，O(n²) 总体。

一题多解：

解法 时间 空间 备注
哈希表两数之和套一层 O(n²) O(n) 去重极其麻烦，不推荐
排序 + 双指针 ✅ O(n²) O(logn)（排序栈） 去重自然：排序后跳过相邻重复值

易错点：

  1. 三处去重缺一不可：i 层跳过重复、命中后 j/k 各自跳过重复段。
  2. 命中后先去重再同时 j++; k--，顺序错了会漏解或重解。
  3. 提前剪枝 nums[0] > 0 可选但能加速。

深度思考：为什么排序后双指针不会漏解？排序保证了”两数之和偏小→右移 j、偏大→左移 k”的单调性，每次移动都能安全排除一类状态（同 11 题的被支配状态论证）。**”排序 + 固定一个 + 对撞找两个”是所有 NSum 问题的母题**，NSum 可递归化。

3. 无重复字符的最长子串 🟨

I: s: str

O: int，不含重复字符的最长子串长度

Cons: 子串必须连续；字符含字母、数字、符号、空格；len(s) <= 5*10⁴，O(n) 目标。

核心思路：子串 + 约束随窗口变化 → 滑动窗口。右指针扩张，出现重复时收缩左边界直到无重复，用哈希集合维护窗口内容。

一题多解：

解法 时间 空间 备注
暴力检查所有子串 O(n³) 或 O(n²)+set O(min(n,c)) 被否决的起点
滑动窗口 + set ✅ O(n)（每字符进出各一次） O(min(n, c)) 通用模板写法
窗口 + last-position 直接跳跃 ✅ O(n) O(c) 左指针一步到位，不用逐格收缩

易错点：

  1. 写法二中必须判断 last[c] >= l：上一次出现的 c 若已在窗口外，不能回跳左指针（例 "abba"，第二个 a 时 last[a]=0 < l=2）。
  2. 收缩条件是 while 不是 if：可能需要连续移出多个字符。
  3. ans 在窗口合法时更新，别放在收缩之前。

深度思考：滑动窗口可行的前提是单调性：右指针右移只会让约束”更紧”，左指针不需要回退。整个算法中 l 和 r 各自单调前进 → 均摊 O(n)。滑动窗口三问：① 什么时候扩（for r）；② 什么时候缩（违反约束 while）；③ 在哪更新答案（通常窗口合法时）。这套模板可直接迁移到 438 / 76 / 209。

438. 找到字符串中所有字母异位词 🟨

I: s: str, p: str

O: List[int]，p 的所有异位词在 s 中的起始索引

Cons: s、p 均为小写字母；窗口定长 len(p)；len(s), len(p) <= 3*10⁴，暴力 O(n·m·26) 会被卡，目标 O(n)。判据：窗口内字母计数 == p 的字母计数。

核心思路：定长滑动窗口 + 字母计数。相邻窗口只有一出一进两个字符变化 → 增量更新计数数组，而不是每个窗口重新统计。

一题多解：

解法 时间 空间 备注
解法一：暴力枚举起点 + 校验 O(n·m·26) O(26) 直觉解
解法二：滑动窗口 + 计数数组比较 O(26n) O(26) 只更新出入的两个字符
解法三：match_count 标量聚合 ✅ O(n) O(26) 判等降到 O(1)

方法一：最直观最容易想到的暴力遍历并校验是否为“异位词”

但是，方法一很不智能，其优化的点在于，如果跳过一些显而易见的“校验”过程。
关键观察：相邻两个窗口之间，只发生了两件事：
最左边的字符滑出去了（c 离开）
最右边的新字符滑进来了（e 进入）
中间重叠的部分（b a / a e）完全没变，却被反复统计了。如果每次只更新”变化了的 2 个字符”，而不是重新数全部 26 个，就能从 O(m) 降到 O(1) 每次。

既然只变两个字符，那我们就维护一个正在运行的计数数组，每次窗口右移时：
窗口从 [i, i+len_p) 滑到 [i+1, i+len_p+1)：

  1. s[i] 的计数 -1 （左边字符滑出）
  2. s[i+len_p] 的计数 +1 （右边字符滑入）
  3. 比较当前计数数组 和 p 的计数数组
    这就是滑动窗口的全部精髓——增量更新，避免重复计算。

O(26) –> O(1)的进一步优化：match_count代表“<字母数量>相同的<数量>”，异位词就是:两个词的每个字母的数量都相同，因此异位词的match_count是26。那么在窗口滑动的过程中，我们之前是比较p_match和s_match这两个[]*26的，现在我们只需要更新p_match，并最后验证是否为26就能判断是否是异位词了。

易错点：

  1. match_count 的维护必须先减后加：滑入/滑出前若该字母计数刚好相等，先 match_count -= 1，变动后再判断加回——顺序反了会漏记状态翻转（作者已在代码注释中标明”先减”的原因）。
  2. window_count == p_count 是 O(26) 的常数比较，别误当 O(1)——解法二整体是 O(26n) 而非 O(n)。
  3. 解法二中出窗口的下标是 i - len_p，别写成 i；窗口是定长的。

深度思考：本题是作者总结的”增量更新，避免重复计算”的标准范本：相邻窗口重叠部分完全没变却被反复统计，只更新变化的 2 个字符即可。match_count 则是更进一步的抽象：把”两个 26 维向量是否相等”的 O(26) 判等，替换为维护一个标量聚合指标（计数恰好相等的字母种类数），判等降为 O(1)。这与 76 题的 valid 变量同源——当需要反复比较高维状态时，提炼一个可随单点更新 O(1) 维护的全局量。

核心洞察
如果一个元素又老又小，它永远不可能”翻盘”成为最大值，可以直接扔掉。
比如窗口里依次进来：[5, 2, 1, 8]
5 进来，当前最大是 5
2 进来，它比 5 小，而且 5 比它晚离开（index 更小），所以 2 永远没机会当最大
1 同理
8 进来，它比 5、2、1 都大，而且更晚离开 —— 之前所有的全都可以扔掉了

引出「单调队列」
维护一个递减的双端队列，队列里存的是索引（不是值），保证：
队首永远是当前窗口最大值的索引
队列里的索引对应的值是严格递减的
每次窗口滑动时：
移除队首：如果队首索引已经滑出窗口，弹出
清理队尾：从队尾开始，把所有 < nums[right] 的索引弹出（它们永远没机会了）
加入新元素：把当前索引从队尾加入
队首就是答案
这就是”智能跳过”——提前淘汰所有不可能成为最大值的元素。

易错点：

  1. 队首”过时”判断用 if 即可（每次窗口只移动一步，最多一个队首过期）；但队尾清理必须 while——新来的大值可能一口气淘汰多个旧候选（作者已在代码注释中标明 if/while 的区别）。
  2. 队列存索引而不是值：只有索引才能判断”是否已滑出窗口”（dq[0] < i-k+1），存值就丢了这个信息。
  3. 收录答案的条件是 i >= k-1：第一个窗口凑满后才开始记录。

深度思考：作者的”核心洞察”值得背下来——又老又小的元素永远不可能翻盘成为最大值，可以直接扔掉。单调队列的正确性建立在这条支配关系上：若 i < j 且 nums[i] <= nums[j]，则 i 在 j 离开窗口前就已失去价值，即 i 被 j 支配。每次入队淘汰全部被支配者，队列内保持严格递减 → 每个元素至多进出队各一次，均摊 O(n)。这与 11 题、42 题的”被支配状态排除法”是同一套论证语言。另见下方扩展2：算法思想先于数据结构名词，单调队列只是这条淘汰规则的”标准化封装”。

nums[nums[i]-1] = 3

nums[i] 现在是 1（刚被改过的！）
nums[i] - 1 = 0
所以实际执行的是：nums[0] = 3
最终 nums 变成了 [3, 2, 1] —— 等于什么都没换！​ 🤯

但是运气差也会退化到O(n^2),如果 pivot 每次都选到最值（最大或最小），分区极度不平衡：
第 1 轮：扫描 n 个，pivot 在最边上，一边 0 个，一边 n-1 个
第 2 轮：扫描 n-1 个
第 3 轮：扫描 n-2 个

T(n) = n + (n-1) + (n-2) + … + 1 = n(n+1)/2 = O(n²)
下面的情况会退化：

  • 数组已经有序（升序或降序）
  • 每次都固定选第一个/最后一个当 pivot（没有随机化）
  • 所有元素都相等，但比较符号写错导致分区不平衡

扩展：严格 O(n) 的实现——BFPRT 算法（Median of Medians）

它不用随机 pivot，而用确定性方法选 pivot，保证每次至少砍掉 30% 的元素：

BFPRT 的精髓在于 pivot 的选法。它不用随机选，而是用一种确定性方法，保证 pivot 不会太偏。

步骤概览

  1. 把数组每 5 个分成一组（最后一组可能不足 5 个）
  2. 每组内部排序，找出中位数（共 n/5 个中位数）
  3. 递归调用 BFPRT，从这 n/5 个中位数中找出它们的中位数 → 这就是 pivot
  4. 用这个 pivot 做 partition
  5. 和快速选择一样，只递归处理包含目标的那一半

为什么能保证砍掉至少 30%？（核心推导）

  • 第一步：5 个一组
    [ a1 a2 a3 a4 a5 ] [ b1 b2 b3 b4 b5 ] [ c1 c2 c3 c4 c5 ] …
    每组 5 个数，排序后中位数是第 3 个。比如第一组排序后：
    小 小 [中位] 大 大
    ↑ 这是组中位数
  • 第二步：所有组的中位数集合
    假设有 m = ⌈n/5⌉ 组，就有 m 个组中位数。
  • 第三步：递归找这些中位数的中位数（记为 M）
    M 是这 m 个中位数的中位数。这意味着：
    至少有 ⌈m/2⌉ 个组中位数 ≤ M（因为 M 是中位数）
    至少有 ⌈m/2⌉ 个组中位数 ≥ M
  • 第四步：关键——M 在全局中处于什么位置？
    取一个 ≤ M 的组中位数，它所在的组里：
    小 小 [中位] 大 大
    这个组里至少有 3 个数 ≤ 这个组中位数 ≤ M。
    所以每个 ≤ M 的组，贡献 至少 3 个 ≤ M 的数。
    一共有 ⌈m/2⌉ 个这样的组，所以：
    至少有 3 × ⌈m/2⌉ 个数 ≤ M
    代入 m = ⌈n/5⌉：
    3 × ⌈n/10⌉ ≥ 3n/10 - 1.5
    也就是说，至少有 ~30% 的元素 ≤ M。
    同理，至少有 ~30% 的元素 ≥ M。
    结论
    pivot M 至少能把数组分成 30% / 70%​ 两部分。无论输入是什么，永远不会出现 0/n 的极端情况。

递归式推导
T(n) = 找 pivot 的代价 + partition 的代价 + 递归处理一边的代价
找 pivot：每组排序 O(1) × n/5 = O(n)，加上递归找中位数的中位数 T(n/5)
partition：O(n)
递归处理：最多处理 7n/10 个元素（因为至少砍掉了 3n/10）
T(n) = T(n/5) + T(7n/10) + O(n)
这个递归式为什么是 O(n)？
画递归树：
每一层的总工作量：n + n×(9/10) + n×(9/10)² + …
因为 1/5 + 7/10 = 9/10 < 1，所以每层的工作量在收缩
总深度有限，总和是 O(n)
严格证明可以用代入法或递归树展开，结论是 T(n) = O(n)。

295. 数据流的中位数 🟥

I: addNum(num: int)；findMedian() -> float

O: 数据流当前所有整数的中位数（偶数个取中间两数平均）

Cons: 数据流式，addNum 与 findMedian 都被高频调用 → 不能查询时再排序；设计题，考察数据结构选型。

核心思路（作者的推导）：不需要全体有序，只需要”中间那 1~2 个数”。中位数天然把集合切成左右两半，只需维护 left 的最大值 与 right 的最小值 → 双堆（left 大顶堆 + right 小顶堆），并维持两条不变式：① 两堆大小差 ≤ 1（约定奇数时 right 多一个）；② left 全部 ≤ right。

我们不需要全部有序，只需要知道排在中间的那 1~2 个数是谁。

比如现在有 6 个数：1,5,6,2,3,4，要计算中位数，可以把这 6 个数从小到大排序，得到 1,2,3,4,5,6，中间 3 和 4 的平均值 3.5 就是中位数。
中位数……可将数值集合划分为相等的两部分。
中位数把这 6 个数均分成了左右两部分，小的那一组记作 left=[1,2,3]，大的那一组记作 right=[4,5,6]。我们要计算的中位数，就来自 left 中的最大值，以及 right 中的最小值。
随着 addNum 不断地添加数字，我们需要：

  • 保证 left 的大小和 right 的大小尽量相等。规定：在有奇数个数时，left 比 right 多 1 个数。
  • 保证 left 的所有元素都小于等于 right 的所有元素。

只要时时刻刻满足以上两个要求（满足中位数的定义），我们就可以用 left 中的最大值以及 right 中的最小值计算中位数。
分类讨论：

  • 如果当前 left 的大小和 right 的大小相等：
    • 如果添加的数字 num 比较大，比如添加 7，那么把 7 加到 right 中。现在 left 比 right 少 1 个数，不符合前文的规定，所以必须把 right 的最小值从 right 中去掉，添加到 left 中。如此操作后，可以保证 left 的所有元素都小于等于 right 的所有元素。
    • 如果添加的数字 num 比较小，比如添加 0，那么把 0 加到 left 中。
    • 这两种情况可以合并：无论 num 是大是小，都可以先把 num 加到 right 中，然后把 right 的最小值从 right 中去掉，并添加到 left 中。
  • 如果当前 left 比 right 多 1 个数：
    • 如果添加的数字 num 比较大，比如添加 7，那么把 7 加到 right 中。
    • 如果添加的数字 num 比较小，比如添加 0，那么把 0 加到 left 中。现在 left 比 right 多 2 个数，不符合前文的规定，所以必须把 left 的最大值从 left 中去掉，添加到 right 中。如此操作后，可以保证 left 的所有元素都小于等于 right 的所有元素。
    • 这两种情况可以合并：无论 num 是大是小，都可以先把 num 加到 left 中，然后把 left 的最大值从 left 中去掉，并添加到 right 中。

最后，我们需要什么样的数据结构？这个数据结构要能高效地执行如下操作：

  1. 添加元素。
  2. 找到最大（小）值。
  3. 删除最大（小）值。

这个数据结构是堆。

left 是最大堆，right 是最小堆。

如果当前有奇数个元素，中位数是 left 的堆顶。
如果当前有偶数个元素，中位数是 left 的堆顶和 right 的堆顶的平均值。

类似于 sorted(itertools.chain(*iterables)) 但返回一个可迭代对象，不会一次性地将数据全部放入内存，并假定每个输入流都是已排序的（从小到大）。

具有两个可选参数，它们都必须指定为关键字参数。

reverse 为一个布尔值。如果设为 True，则输入元素将按比较结果逆序进行合并。要达成与 sorted(itertools.chain(*iterables), reverse=True) 类似的行为，所有可迭代对象必须是已从大到小排序的。

从 iterable 所定义的数据集中返回前 n 个最大元素组成的列表。如果提供了 key 则其应指定一个单参数的函数，用于从 iterable 的每个元素中提取比较键 (例如 key=str.lower)。 等价于: sorted(iterable, key=key, reverse=True)[:n]。
